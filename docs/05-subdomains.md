# 05 · Субдомены и ссылка между хостами

Здесь описано, как один репозиторий отдаёт несколько hostname'ов:
`sofexpo.org` (центр) + `foodera.sofexpo.org`, `buildpro.sofexpo.org`, `agropro.sofexpo.org`,
`worldedu.sofexpo.org`, `ecomretail.sofexpo.org` (выставки). Это **архитектура ссылок**, а не
верстка: меняется только то, какой хост считает себя владельцем страницы.

## 1. Два режима, один проект

| Режим                  | Что публикуется                                                                                                                                                                                                  | Когда нужен                                                                        |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `alias` (по умолчанию) | Всё на `sofexpo.org`, кластер выставки живёт по `/events/{slug}/…`                                                                                                                                               | Пока хостинг/DNS не подтверждены. Вывод побайтово совпадает с однодоменной сборкой |
| `subdomain`            | Кластер каждой регулярной выставки уезжает на свой hostname (`/`, `/exhibitors/`, `/visitors/`, `/program/`); центр оставляет площадку, хаб-разделы, афишу, **весь редакционный контент** и юридические страницы | Когда клиент готов добавить 5 A/CNAME-записей и 5 property в Search Console        |

Режим — одна переменная: `PUBLIC_HOSTS_MODE=subdomain`. Никаких `if` в компонентах:
единственная функция, которая строит ссылки, — `localize()` в `src/i18n/config.ts`,
она спрашивает владельца пути в `src/data/host-map.json` (через `scripts/host-rules.mjs`).

Правило: **хост решается один раз, в одном месте.** Реализация `ownerOf()` лежит в
`scripts/host-rules.mjs` и импортируется и приложением, и Node-скриптами — иначе
SSG и проверка разъехались бы через полгода.

## 2. Кто что публикует (матрица владения)

| Контент                                                          | `alias`                                                                    | `subdomain`                                                                                                       |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Главная центра, площадка, залы, техспецификация                  | `sofexpo.org`                                                              | `sofexpo.org`                                                                                                     |
| Хабы «Экспонентам / Посетителям / Организаторам»                 | `sofexpo.org`                                                              | `sofexpo.org`                                                                                                     |
| Афиша `/events/`, архив `/events/past/`                          | `sofexpo.org`                                                              | `sofexpo.org`                                                                                                     |
| 4 страницы выставки (обзор, экспонентам, посетителям, программа) | `sofexpo.org/events/{slug}/…`                                              | `{host}/{locale}/…` — **без** `/events/{slug}/`                                                                   |
| Старый путь `sofexpo.org/events/{slug}/…`                        | —                                                                          | заглушка-переезд: `noindex,follow` + `<link rel="canonical">` на новый хост + `meta refresh` + 301 в `_redirects` |
| Новости и лонгриды (`/news/`, `/articles/`)                      | `sofexpo.org`                                                              | `sofexpo.org` — **не дублируются** на хост выставки                                                               |
| Поиск, RSS, `llms.txt`, `/request-stand/`, `legal/*`             | `sofexpo.org`                                                              | `sofexpo.org` (хост выставки ссылается абсолютным URL)                                                            |
| Промо-полоса и мега-меню                                         | везде одни и те же ссылки; чужие пути становятся абсолютными автоматически |                                                                                                                   |

Почему редакционные тексты остаются на центре: это единственные страницы, которые копят
возраст и ссылки год за годом. Размазать их по пяти хостам — значит каждый раз начинать
накапливать с нуля. Хост выставки получает транзакционный кластер («забронировать стенд»,
«как добраться», «программа») — то, что ищут по названию выставки.

## 2b. Идентичность хоста (своя у FOODERA, общая у остальных)

Хост несёт не только свои URL, но и своё лицо. Реестр — `src/data/brand-map.json`: одна запись =
одна выставка со своей палитрой, названием знака и правом на орнамент. Файлов, где есть `if (host
=== …)`, — ноль; хост меняет токены, всё остальное перекрашивается само.

Что делает сборка на брендированном хосте (см. `docs/04` §5c):

| Что                                           | Где берётся                                       | Эффект                                                        |
| --------------------------------------------- | ------------------------------------------------- | ------------------------------------------------------------- |
| `<html data-brand="foodera">`                 | `CURRENT_BRAND` из `src/data/hosts.ts`            | селектор для блока токенов                                    |
| блок токенов                                  | `brandCss()` — последним в `<head>`               | весь сайт выставки в своих цветах, специфичность бьёт `:root` |
| `theme-color`                                 | `palette.evergreen`                               | адресная строка мобильного браузера в цвет поля               |
| `og:site_name`                                | `name + sub` («FOODERA EXPO 2026»)                | раскрывалка шарится от имени выставки, а не центра            |
| `favicon.*`, `apple-touch-icon.png`, `og.jpg` | `public/brand/<id>/`, если каталог есть           | своя иконка и своя карточка; у остальных хостов — центр       |
| орнамент                                      | `Ornament.astro`, только при `ornament: "islimi"` | полоса под hero и над подвалом                                |

Как добавить выставку (BUILDPRO и прочие — ровно эти четыре шага):

1. векторный логотип организатора → `public/brand/<id>/logo.*`; снять цвета, посчитать контраст
   каждой пары «текст/фон» и вписать только прошедшие 4.5:1 для текста (крупному — 3:1);
2. запись в `src/data/brand-map.json` (`host`, `name`, `sub`, `ornament`, `palette`);
3. `public/brand/<id>/favicon.svg` — знак в квадрате 64×64, без мелких деталей;
4. `node scripts/build-assets.mjs && node scripts/build-hosts.mjs --mode subdomain &&
node scripts/check-hosts.mjs` — иконки и карточка соберутся из svg, проверится, что ни одна
   ссылка не съехала.

Цвета FOODERA в `brand-map.json` **предварительные**: их снимали глазами с растрового PNG, который
прислал заказчик (в песочнице файла нет — он был только в переписке), контраст посчитан от этих
значений. Как только придёт вектор, значения переснимаются с него и правятся в одном файле —
ни один компонент трогать не нужно.

## 3. URL-схема хоста выставки

    https://foodera.sofexpo.org/            → выбор языка (двери ведут на /ru/ и /en/ этого же хоста)
    https://foodera.sofexpo.org/ru/         главная страницы FOODERA (даты, разделы, статистика, FAQ, заявка)
    https://foodera.sofexpo.org/ru/exhibitors/   форматы стендов, дедлайны, смета
    https://foodera.sofexpo.org/ru/visitors/     билеты, регистрация, маршрут
    https://foodera.sofexpo.org/ru/program/      форумы, спикеры, расписание
    …всё то же на /en/

Локаль остаётся в URL (`/ru/`, `/en/`): дублирование поддомена × язык иначе не развести,
и `hreflang` обязан указывать на страницу того же хоста.

## 4. Семь правил межхостовой перелинковки

1. **Один путь = один владелец.** Страница собирается ровно на одном хосте; проверка —
   `scripts/check-hosts.mjs` (правило «path built on N hosts»).
2. **Чужой путь → абсолютный URL.** Внутри своего хоста — относительная ссылка, на чужой —
   `https://sofexpo.org/ru/venue/…`. Это делает `localize()`, руками абсолют не пишется.
3. **Свой хост не повторяем в URL.** `https://foodera.sofexpo.org/ru/program/` внутри
   foodera — ошибка (проверяется тем же скриптом), потому что так рождается второй канонический
   адрес для одной страницы.
4. **`hreflang` и переключатель языка не прыгают между хостами.** ru↔en — всегда пара
   одного хоста; `x-default` — `/` этого хоста.
5. **Старый путь не бросаем 404.** `sofexpo.org/events/{slug}/…` = 301 в `_redirects`
   (Cloudflare Pages / Netlify) плюс HTML-заглушка с `canonical` на новый хост для площадок,
   где редиректов нет. Заглушка `noindex,follow`: она отдаёт ссылочный вес, но не плодит дублей,
   и `scripts/prune-sitemap.mjs` её из sitemap выкидывает.
6. **Якоря — те же, что и в однодоменной схеме** (см. `docs/03` §3): текст ссылки = ключ
   целевой страницы, «Подробнее» только на карточках.
7. **Ссылки из хаба — на главную хоста, а не на глубокую страницу.** Карточка в афише ведёт
   на `https://{host}/{locale}/`; разделы пользователь выбирает уже там. Иначе deep-link
   забирает ссылочный вес у главной страницы события — а именно она должна ранжироваться
   по запросу «FOODERA EXPO».

## 5. Почему субдомен, а не папка: честно

| Аргумент «за»                                                                                                                             | Аргумент «против»                                                                                               |
| ----------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Запрос «agropro expo samarkand» матчится доменом — CTR в выдаче выше, бренд читается в адресе                                             | Google склейвает репутацию домена и поддомена **слабее**, чем страницы внутри папки                             |
| У каждой выставки свой sitemap, свои `robots.txt`, своя property, свой дашборд в GA4 и Search Console — легко показать отчёт организатору | Ссылки с партнёрских сайтов, которые уже стоят на `sofexpo.org/events/foodera-expo/`, придётся переадресовывать |
| Контент и навигация события изолированы: менеджер выставки правит свой хост, не задев остальные                                           | 6 сборок вместо одной, 6 деплоев, 6 наборов SSL/DNS                                                             |
| Промо-материалы (баннер, PDF, бейдж) печатают короткий адрес `foodera.sofexpo.org`                                                        | Если выставка пройдёт один раз и закроется, её хост надо грамотно отдавать назад (301 на архив), а не бросать   |

Вывод, заложенный в код: **режим переключается, а не переписывается.** Если клиент не хочет
6 хостов, остаётся `alias` + `public/`-редиректы на vanity-домены (например
`foodera.uz → sofexpo.org/events/foodera-expo/`) — бренд в печати тот же, вес не делится.
Список таких редиректов генерируется из того же `host-map.json` и попадает в
`dist-hosts/redirects.vanity.md`.

## 6. Команды

    npm run build                 # режим alias, 152 страницы (75 × 2 локали)
    npm run check                 # build + seo-audit (ворота приёмки)
    npm run build:hosts           # 6 сборок в dist-hosts/<host>/ + robots + _redirects + аудиты
    # внутри каждой сборки: astro build → prune-sitemap → rewrite-host-links → seo-audit --host --peers
    node scripts/check-hosts.mjs --dir dist-hosts --mode subdomain   # целостность межхостовых ссылок

`seo-audit` знает про соседей: параметр `--peers dist-hosts` учитывает входящие ссылки с
других хостов, чтобы страница события не выглядела сиротой, хотя на неё ссылается центр.

## 7. Деплой: что именно делать

1. **DNS.** 5 A/CNAME-записей на тот же проект, что и `sofexpo.org` (`*.sofexpo.org` —
   wildcard-сертификат, если хостинг его даёт).
2. **Хостинг.** Cloudflare Pages привязывает к проекту один hostname за раз, поэтому чище
   всего делать по одному проекту на хост и выкладывать артефакт из `dist-hosts/<host>/`
   (команда сборки у каждого своя: `SITE=https://{host}/ npx astro build`).
   Свой nginx проще: один `server_name` на каждый каталог `dist-hosts/<host>`,
   `try_files $uri $uri/ /index.html;`.
3. **`robots.txt` и sitemap** генерируются на хост автоматически (`build-hosts.mjs`):
   `Sitemap: https://{host}/sitemap-index.xml`.
4. **Search Console**: domain property `sofexpo.org` + по URL-prefix property на каждый
   поддомен; отправить sitemap каждого.
5. **GA4 / пиксели**: измерения `hostname` обязательны, заявки с хоста выставки помечать
   `utm_source=foodera-host`, чтобы не потерять атрибуцию.
6. **Форма** остаётся одна (`sofexpo.org/ru/request-stand/`? сейчас — mailto), но `?event={slug}`
   подставляется на любом хосте, так что заявок «не из того события» не будет.

## 8. Риски и как они закрыты кодом

| Риск                                         | Механизм защиты                                                                                                     |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Дубль контента на двух хостах                | матрица владения + `check-hosts` падает, если путь собран на 2+ хостах                                              |
| Ссылка в никуда после переезда               | 40 правил 301 в `_redirects` + HTML-заглушка с canonical                                                            |
| `hreflang` смотрит не туда                   | `localizeSameHost()`; проверка «hreflang stays on host»                                                             |
| Относительная ссылка на несобранную страницу | пост-сборка `rewrite-host-links.mjs` делает её абсолютной; `seo-audit` всё равно нашёл бы битвую ссылку             |
| Разъезд данных между SSG и проверками        | `host-map.json` — единственный источник имён хостов                                                                 |
| Пустые/битые ассеты на поддомене             | сборка каждого хоста содержит свой `public/` (фото, PDF) — 404 невозможны; дублирование ~0,5 МБ принято сознательно |

## 9. Что должен подтвердить клиент (без этого не включаем `subdomain`)

1. Имена: `foodera` / `buildpro` / `agropro` / `worldedu` / `ecomretail` — коротко, без `-expo`,
   в нижнем регистре, без подчёркиваний. Если бренд требует иначе — правится одна строка в
   `src/data/host-map.json`, и вся ссылка перестраивается сама.
2. Домен верхнего уровня: `sofexpo.org` или `sofexpo.uz` (у sofexpo.uz уже есть контент — надо
   решить, кто из двух главный, и 301'ить второго).
3. Хостинг с неограниченным числом custom hostnames (Cloudflare Pages / Vercel / свой nginx).
4. Промоутерс: `promotors-show-samarkand` сознательно **без** хоста — прошедшая разовая
   редакция не получает ни домена, ни property.
5. Нужны ли поддомены _следующих_ брендов (если появится 7-я выставка — её просто дописывают
   в `host-map.json`; сборка и проверки подхватят без правки компонентов).
